🔧 Fix Foreign Key Constraint Error

Current Error: #1451 - Cannot delete or update a parent row: a foreign key constraint fails

This error occurs when trying to delete a user because activity_logs table references that user.

The Problem

The activity_logs table is linked to the users table with a foreign key. Currently, when you delete a user, the system refuses because there are activity log entries pointing to that user. We need to add ON DELETE CASCADE so deleting a user automatically deletes their activity logs.

1Open phpMyAdmin

Go to: http:

2Select Database

In the left sidebar, click: scancare_db

3Click SQL Tab

At the top menu, click: SQL

A text area will appear for entering SQL queries.

4Paste This SQL Command

Copy and paste the following into the SQL text area:

ALTER TABLE activity_logs DROP FOREIGN KEY fk_activity_logs_user; ALTER TABLE activity_logs ADD CONSTRAINT fk_activity_logs_user FOREIGN KEY (user_id) REFERENCES users (user_id) ON DELETE CASCADE ON UPDATE CASCADE;

5Execute the Query

At the bottom of the SQL text area, look for and click the Go button.

The query will execute.

6Verify Success

You should see a green success message:

Your SQL query has been executed successfully.

If you see an error, check that:

  • You're in the correct database (scancare_db)
  • The SQL script was pasted exactly as shown
  • The constraint name fk_activity_logs_user is correct

7Test It Works

Now you should be able to delete users without getting the foreign key error.

To test:

  1. Go to the users table in phpMyAdmin
  2. Try to delete any user row
  3. It should delete successfully along with their activity logs
What This SQL Does:
  • Line 1-2: Removes the old foreign key constraint
  • Line 3-7: Creates a new foreign key with ON DELETE CASCADE
  • Result: Deleting a user automatically deletes their activity logs
